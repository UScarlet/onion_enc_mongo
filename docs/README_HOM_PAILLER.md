## Причины
Для слоев HOM (гомоморфные агрегации) и HOPE (сравнение с сохранением порядка) была выбрана криптосистема Пэйе (Paillier). Выбор обоснован тем, что её профиль утечек строго ограничен её функциональными свойствами. Она раскрывает ровно ту информацию, которая извлекается в результате разрешенных вычислений (например, сам факт выполнения сложения для HOM-слоя, или только знак разности при использовании специального ключа сравнения в HOPE-слое).

были также рассмотрены остальные системы:
1. Криптосистема RSA и классический Эль-Гамаль (ElGamal)
Минусы для БД: Они умеют только умножать зашифрованные числа.

2. Goldwasser-Micali (GM)
Минусы для БД: Она гомоморфна относительно побитового XOR. А умножения нет

3. Экспоненциальный Эль-Гамаль (Exponential ElGamal)
Это аддитивная модификация классического Эль-Гамаля.
Минусы для БД (Критический): Чтобы расшифровать результат, нужно вычислить дискретный логарифм. Если сложить две зарплаты (например, 50 000 и 60 000), тебе придется искать логарифм для числа 110 000. Это решаемо. Но если база данных сложит зарплаты 10 000 сотрудников, сумма будет гигантской. Вычисление дискретного логарифма от такого числа займет годы.

4. Окамото — Утияма (Okamoto-Uchiyama)
Плюсы: Аддитивно-гомоморфная система (поддерживает сложение). Вычислительно шифрование происходит даже немного быстрее, чем в системе Пэйе.
Минусы для БД: Она менее стандартизирована. В ней обнаружены некоторые уязвимости к атакам на основе подобранного шифртекста (CCA), если применять ее "в лоб".
Вердикт: кажется хорошая система, но проигрывает Пэйе в популярности и надежности готовых реализаций.

5. Криптосистема Пэйе (Paillier)
Плюсы: Идеальная математика для СУБД: Поддерживает сложение шифртекстов и умножение шифртекста на открытую константу.
Быстрая расшифровка больших сумм: В отличие от Экспоненциального Эль-Гамаля, расшифровка в Пэйе не требует вычисления дискретного логарифма.
Экосистема Python: Для Пэйе существует стабильная и протестированная библиотека на Python — phe (Python Homomorphic Encryption).
Минусы для БД: Размер шифртекста. При ключе в 2048 бит исходное число (даже если это цифра "5") превратится в строку длиной около 600 символов. База данных будет "разрастаться" (с другой стороны база данных сама по себе подразумевает большое количество памяти).  Но это неизбежная плата за безопасность и гомоморфность.

## Математическая модель криптосистемы Пэйе (Paillier)

Криптосистема Пэйе является вероятностной асимметричной криптосистемой. 
Ее криптографическая стойкость базируется на вычислительной сложности задачи определения n-го вычета по модулю n^2. 
Процесс работы алгоритма делится на три основных этапа:

### 1. Генерация ключей (Подготовительный этап)
На этапе инициализации система формирует связанную пару ключей (открытый и закрытый).

a) Выбираются два больших простых числа $p$ и $q$, после чего вычисляется их произведение $n = p \cdot q$.  

б) Вычисляется параметр $\lambda = \text{НОК}(p-1, q-1)$.  

в) Выбирается случайное число $g$ из мультипликативной группы $Z_{n^2}^*$. Для работы алгоритма определяется специальная функция $L(x) = \frac{x - 1}{n}$, применяемая к целым числам $u \equiv 1 \bmod n$.  
(на практике для ускорения часто берут $g = n + 1$)

г) Вычисляется параметр $\mu = (L(g^\lambda \bmod n^2))^{-1} \bmod n$.  

В результате формируется:<br>
Открытый ключ для шифрования: $k = (n, g)$.  <br>
Секретный (закрытый) ключ для дешифрования: $(\lambda, \mu)$. 

### 2. Шифрование (от открытого текста к шифртексту)
Для преобразования открытого числового значения $m \in Z_n$ в шифртекст $c$, алгоритм использует фактор рандомизации, что обеспечивает семантическую безопасность.
Выбирается случайное число $r$ из $Z_n^*$.  
Шифртекст вычисляется по формуле модульной арифметики:
$c = g^m \cdot r^n \bmod n^2$.  

### 3. Дешифрование (восстановление открытого текста)
Для получения исходного значения из криптограммы $c$ применяется секретный ключ.
Дешифрование выполняется по формуле:
$m = L(c^\lambda \bmod n^2) \cdot \mu \bmod n$.  

### 4. Аддитивно-гомоморфные свойства
Ключевой особенностью криптосистемы Пэйе, применяемой для слоя HOM в базах данных, является аддитивная гомоморфность. 
Это математическое свойство позволяет выполнять сложение зашифрованных значений без их предварительного расшифрования:  
Произведение двух криптограмм по модулю $n^2$ является криптограммой суммы соответствующих им открытых текстов:
$D(E(m_1) \cdot E(m_2) \bmod n^2) = m_1 + m_2 \bmod n$. 

### 5. Гомоморфное умножение на константу (Скалярное умножение)

В криптосистеме Пэйе невозможно перемножить два зашифрованных значения между собой так, чтобы получить шифртекст их произведения. Однако можно умножить зашифрованное значение на открытое число (константу) $k$.

Возведение криптограммы в степень $d$ позволяет умножить содержащийся в ней открытый текст на константу $d$: <br>
$D(E(m)^d \bmod n^2) = d \cdot m \bmod n$.

Если разобрать это по шагам:<br>
У нас есть шифртекст исходного сообщения $m$, который вычисляется как:
$$c = (g^m \cdot r^n) \bmod n^2$$

Нам нужно умножить скрытое значение $m$ на открытую константу $k$. Для этого сервер возводит полученный шифртекст $c$ в степень $k$ по модулю $n^2$:
$$c_{new} = c^k \bmod n^2$$

Если мы подставим исходную формулу шифрования и раскроем скобки по правилам степеней, мы увидим, как преобразуется внутренняя структура:
$$c^k = (g^m \cdot r^n)^k \bmod n^2 = (g^{k \cdot m} \cdot r^{k \cdot n}) \bmod n^2$$

Сгруппируем переменные:$$c^k = g^{k \cdot m} \cdot (r^k)^n \bmod n^2$$

Обратим внимание на итоговую формулу. 
Значение $r$ изначально было просто случайным числом (фактором рандомизации). 
Значит, $r^k$ — это тоже просто какое-то случайное число (назовем его $r'$).
В итоге выражение принимает классический вид валидного шифртекста Пэйе:
$$g^{(k \cdot m)} \cdot (r')^n \bmod n^2$$
(за шифртекст m можно принять значение $(k \cdot m)$ )<br> 
При расшифровке этого нового шифртекста $c_{new}$ секретным ключом, алгоритм закономерно выдаст нам значение $k \cdot m \bmod n$.

## Ограничения
На текущий момент возможна работа только с неотрицательными целыми значениями.
